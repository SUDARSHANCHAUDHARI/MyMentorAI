# Day 14: Swagger and OpenAPI

## Objective

Use API documentation as a testing source of truth.

## Learn

- Swagger UI
- OpenAPI contracts
- Endpoints
- Request schemas
- Response schemas
- Required vs optional fields
- Contract gaps

## Practice

Open a public Swagger or OpenAPI example and pick one endpoint.

Record:

- Method and path
- Required parameters
- Request body shape
- Expected status codes
- Response fields
- Edge cases suggested by the contract

Compare the contract to at least one real request in Postman.

## Mini Quiz

1. What is an API contract?
2. Why is Swagger useful for testers?
3. What is a required field?
4. What is one contract detail that can become a test case?
5. What should you do if behavior and documentation disagree?

## Challenge

Turn one OpenAPI endpoint into three test scenarios: positive, negative, and edge case.
