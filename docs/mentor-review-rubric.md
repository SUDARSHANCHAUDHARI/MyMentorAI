# Mentor Review Rubric

Use this to review each day's check-in like a senior engineer reviewing a teammate's work.

## Daily Review

Score each area from 1 to 5.

| Area | What Good Looks Like |
| --- | --- |
| Understanding | Explains the concept in plain English |
| Practice | Completed the hands-on task, not just reading |
| Evidence | Added notes, screenshots, exports, or test files where relevant |
| Debugging | Captured mistakes and fixes honestly |
| Communication | Explains blockers and questions clearly |

## Review Response Format

```text
Review for Day X

Score:
- Understanding: /5
- Practice: /5
- Evidence: /5
- Debugging: /5
- Communication: /5

What went well:

What to improve:

Question to answer before moving on:

Decision:
- Move to next day
- Repeat this day
- Do a short repair exercise
```

## When To Slow Down

Slow down if:

- The learner can run a request but cannot explain why it works.
- Notes are copied definitions instead of personal understanding.
- Tests only check status codes.
- Negative scenarios are missing.
- The same mistake appears multiple days in a row.
- The learner avoids writing down confusion.

## When To Increase Challenge

Increase challenge if:

- Tasks are completed quickly with clear explanations.
- The learner asks deeper "why" questions.
- Tests include meaningful assertions.
- Mistakes are being debugged independently.
- Documentation is clear enough for another person to follow.
